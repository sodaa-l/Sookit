# 决策 59. 表格视图新增「ID」列（format_id），插在 选择 与 类型 之间（2026-10-21）

> 决策索引：[DEVELOPMENT.md](../DEVELOPMENT.md#决策索引)（编号与代码注释里的「决策 59」一一对应）

## 背景

用户在表格视图里看不到每一行到底是 yt-dlp 的哪个格式：同一个「视频+音频」可能是
`http-2176`（渐进式成品），也可能是 `137+140-1`（合并组合）；同一个「音频流」可能是
`140-1`（129kbps）也可能是 `hls-audio-128000-Audio`。要和 `yt-dlp -F` 的输出对号、
或者判断某行背后是独立流还是成品，都需要 `format_id` 本身。

要求：在**选择框**和**类型**之间插一列「ID」。

## 结论

`src/sookit/pages/youtube_page.py`：

1. `_FormatTable.COL_FACTORS` 由 5 列改 6 列：`[40, 73, 73, 86, 70, 40]`
   （选择 / ID / 类型 / 质量 / 编码 / 语言）。权重按「各列必须单行放下的最长文案 +
   32px 单元格内距」反推，见下面的补记。
2. `setColumnCount(6)` + 表头 `["选择", "ID", "类型", "质量", "编码", "语言"]`。
3. 填充：第 1 列 = `fmt['format_id']` 原文，**tooltip 给全文**；类型/质量/编码/语言
   顺延到第 2/3/4/5 列；质量列同样挂 tooltip（长 `format_note` 会截断）。
4. 表格 `setWordWrap(False)` + `setTextElideMode(ElideRight)`：文案一律单行省略号，
   不按词换行撑高行高（第二轮配平时加的）。
5. 勾选列仍是第 0 列 —— `_on_format_item_changed()`（互斥勾选）和 `do_download()`
   （收集勾选行）只认 `column 0`，**无需改动**。
6. 右边线 `_sync_edge_rules()` 的列尾位置是 `verticalHeader().width() + sum(columnWidth)`
   动态算出来的，新增列自动被算进去，不用碰决策 56 的代码。

## 没采用的替代做法

- **ID 放最后一列**：用户明确要求夹在「选择」和「类型」之间——一眼就能看到这行是哪条流，
  放最后会被右侧留白/滚动条挤到视口边缘。
- **显示拼接后的选择器**（如 `137+140-1`）：那是「视频+音频」行合出来的组合，独立视频流
  行根本没有，而且和 `do_download()` 传给 yt-dlp 的 spec 是不同概念（一行 ≠ 一次下载）。
- **ID 列用等宽字体 / 居中**：与其余列风格不一致；长 ID 居中后左右都参差，更难扫。
- **做成可点击复制**：超出「看一眼 ID」的需求；tooltip 已经能看到全文。

## 实测效果

1131×731（用户窗口尺寸，表格宽 594、viewport 558）：列宽
`[55, 102, 102, 120, 97, 55]`。YouTube 多语言样本 49 个格式的 ID **全部单行放得下**
（`140-0` / `251-1` / `233-0` …）；X 样本 9 条里 8 条放得下，只有
`hls-audio-128000-Audio` 这类（实需 185px）省略号截断、悬停看全文。右边线仍等于
`vh + 列宽和`、无横向滚动条，两枚下载按钮仍是 240 宽。

| 窗口 | 列宽（选择 / ID / 类型 / 质量 / 编码 / 语言） | 说明 |
|---|---|---|
| 966×731 | `[50, 77, 77, 91, 74, 50]` | 每列 ≥ `COL_MIN(50)`；此档放不下全部文案（见风险 3） |
| 1131×731 | `[55, 102, 102, 120, 97, 55]` | 类型/质量/编码/语言全部单行放下，ID 只截断超长 ID |
| 1440×900 | `[74, 135, 135, 160, 130, 74]` | |

### 补记 1：第一轮权重（质量列不够宽）

第一版 `[44, 72, 90, 80, 90, 50]` 在 1131 档质量列只有 104px，用户反馈「质量列分到的宽度
不够」，要求压缩 ID 与类型腾位置。先用真机字体量出各列必须放下的宽度（含 32px 内距）：

| 列 | 代表性文案 | 需要宽度 |
|---|---|---|
| 类型 | `视频+音频` | 94px |
| 质量 | `1080p 60fps` / `Default, high` | 111px |
| 编码 | `avc1+aac` | 92px |
| 语言 | `ko` | 47px |

于是调成 `[42, 46, 78, 98, 80, 47]`：ID 93→62px、类型 117→106px、质量 104→133px。

### 补记 2：第二轮回调 ID 列（用户：ID 压太窄）

ID 收到 62px 后只剩 7 个字符位（`http-2176` 需 98px），用户反馈「ID 压的太窄了」。改按
「先保 ID 的常用形态、再保其它列下限」重排：把 `http-2176`（9 字符）算作 ID 的硬需求 =
98px，六列需求之和 98+94+111+92+47+55 = 497px，而 1131 档可用 534px → 放得下，于是给出
`[40, 73, 73, 86, 70, 40]`：**ID 102px**（比第一轮多 40px）、质量 120px（仍高于下限 111px）、
类型/编码/语言各留 6~11px 余量。

顺带发现长 ID 会**按词换行**（`hls-` 换行成两行、行高被撑高、表格参差不齐），因此加了
`setWordWrap(False)` + `ElideRight`：一律单行省略号 + tooltip 看全文，9 行 X 样本的行高
重新变得整齐。代价是 `hls-audio-128000-Audio` / `-64000-` / `-32000-` 三条只显示
`hls-audi…`、彼此看不出区别——它们靠「质量」列的 128/64/32kbps 和 tooltip 区分。

**第二轮验证**（截图 + 字体度量，`tmp_id/shot59c.py`，225% 缩放）：YouTube 49/49 条 ID 单行
放得下、X 6/9 条放得下（3 条超长 ID 截断，实需 177~185px）；结构断言 24/24、宽度断言 8/8。

填充结果抽样：

- YouTube 多语言样本（49 个格式）：`140-0` / `140-1` / `251-0` / `251-1` / `250-0` / `250-1` …
- X 样本（9 个格式）：`http-2176` / `http-832` / `http-288` / `hls-audio-128000-Audio` /
  `hls-audio-64000-Audio` / `hls-audio-32000-Audio` …

## 验证

`verify59.py`（24/24）与 `verify59b.py`（列宽/字体度量 8/8，其中 1131 与 1440 档要求类型、
质量、编码、语言四列都放得下代表文案，ID 只做记录）、`shot59c.py`（第二轮按用户批准出的
225% 截图 + 逐条 ID 度量）：

- 列数 6、表头文案与顺序完全一致；
- 每一行的 ID / 类型 / 语言单元格都等于 `_formats_data[row]` 里对应字段，ID tooltip 也在；
- 勾选列仍是第 0 列，且「视频+音频」互斥仍然生效（手动勾第 2 条，第 1 条自动取消）；
- 右边线 x == `min(vh + Σ列宽, 表宽 − 14)`，列宽和 ≤ viewport（无横向滚动）；
- 966 / 1131 / 1440 三档窗口下每列 ≥ `COL_MIN`。

## 风险

1. **列宽是零和的**：1131 档六列需求之和已到 497px / 可用 534px，再给某列加宽只能从别的列
   扣（第二轮就是把质量 133→120px 让给 ID 62→102px）。以后再加列必须重排 `COL_FACTORS`，
   不要直接追加。
2. **长 ID 不是全文可见**（省略号 + tooltip）——这是「一列塞下多种站点 ID」的必然取舍。
3. **超长 ID 不够区分**：`hls-audio-128000-Audio` / `64000` / `32000` 三条截断后都是
   `hls-audi…`，只能靠质量列（128/64/32kbps）或 tooltip 区分。
4. **窄窗必然截断**：966×731 时表格仅 466px、可用宽度 430px，六列下限之和 447px 已超出，
   类型/质量/编码都会省略号截断（`COL_MIN = 50` 托底还会让列宽和略微顶到 viewport 边缘，
   竖线退到 `表宽 − 14`，与决策 56 同一兜底；不出现横向滚动条）。
5. **列索引变了**：任何按列号读写单元格的代码必须用新索引；勾选仍是 0，ID 是 1，
   类型/质量/编码/语言是 2/3/4/5。新增列请改 `COL_FACTORS` 与表头两处并同步填充。
