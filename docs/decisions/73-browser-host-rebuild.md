# 决策 73. 检测旧浏览器桥接并在源码模式后台重建

## 问题

新增 monitor 等动作后，仅重载扩展不会更新独立冻结的 native host。旧 host 会在启动 Sookit 前以“不支持的浏览器请求”拒绝动作。决策 70 的文件与注册路径校验无法发现这种程序与源码不一致的情况。

## 能力诊断

- native host 增加本机命令行参数 `--bridge-capabilities`，在设置 Windows 二进制输入输出后直接返回 Native Messaging 编码的动作列表，不读取配置、不连接 GUI、不启动应用。浏览器请求仍按原有扩展 origin 和动作白名单校验，不新增浏览器协议动作。
- 本地文件完整后，诊断当前布局的实际 exe，要求其声明包含当前 `BROWSER_ACTIONS | HOST_CONTROL_ACTIONS` 的全部动作。旧版会拒绝这个命令行参数，其正常拒绝回执也判为不兼容；非法回执、启动失败及 3 秒超时也属于异常。
- 注册路径正确且 exe 存在不再等于“桥接正常”。源码模式可修复旧程序；安装版旧程序不提供无效的注册修复，明确提示更新或重新安装。文件不完整的原有拒绝边界继续保留。

## 修复与线程

- 源码模式先校验组件，必要时使用当前 Python 环境执行开发注册脚本 `--build-only`：重建冻结 host，并恢复 `source-launch.json` 和清单，不写注册表、不安装依赖或下载程序。
- 构建失败或重建后文件/能力检查不通过时停止，不写 HKCU。重建并复查通过后才执行原有当前用户注册修复；安装版仅在程序能力匹配时修复注册，不修改安装目录、不提权、不写 HKLM。
- 修复调用移至后台 QThread，避免 PyInstaller 构建阻塞界面；修复期间禁用修复和重新检查按钮，并防止重复调用。主线程接收完成信号后重新诊断，仅复查正常才提示成功；失败时详情和通知展示具体原因。
- 线程无页面 parent，由模块级集合持有至 finished；页面提前销毁会断开绑定槽，完成清理不捕获页面。关闭页面不终止正在执行的文件重建。

## 验证

浏览器相关离线回归覆盖旧能力列表、旧 host 拒绝回执、损坏/超时、源码重建后校验再注册、构建失败或仍旧过期时不写注册表、安装版引导更新，以及 UI 事件循环响应、重复点击、失败重试与页面销毁。真实源码 host 重建使用实际构建链；注册写入替换为测试记录器，并核对本机注册表前后不变。
