# 决策 56. 嗅探页表格视图右下开口：取消底边、右边线落在列尾（2026-10-21）

## 背景

决策 55 给格式表格补了一圈四边闭合的 1px 外框（`setBorderVisible(True)` + `setBorderRadius(8)`）。
用户看过效果后贴了截图（在最后一列「语言」右缘画了一条红线）并提要求：

> 表格视图取消下闭合，且右闭合得改动到我画的红线的位置上

红线位置换算（截图 2547×1646、界面缩放 2.25 —— 由「下载按钮代码固定 240 逻辑宽、实测 540 物理」反推）：

- 红线中心 x ≈ 2481 物理 = **1102 逻辑**，距窗口右缘 **27px**；
- y 从表头顶到原底边，**覆盖表格全高**。

也就是：**底边不要线，右边线不要贴窗口边，要落在「最后一列的列尾」上**。对齐时确认了另一件事：
去掉外框后四角是直角（不再是原来的 8px 圆角），用户接受，选了「直角」而不是「保留 8px 圆角」。

> 后续补充（装上构建实测后）：**空表时要有下边线**（那时既没有行号列也没有滚动条，开口像没画完），
> 一有数据就恢复右下开口 —— 见下方「补记 3」。因此本文的「右下开口」准确说是
> **有数据时开口、空表时是一个四条边都落在列尾上的完整矩形**。

## 根因

决策 55 补的外框是 `QTableView` 自己的 `border`，只能贴着**控件四周**画。而这张表为了「滚动条贴窗口右缘」
铺满到了窗口右缘（决策 54），列宽又只分到 `viewport - RIGHT_RESERVE(24)`，于是：

- 右边线落在视口最右（≈窗口边），把右侧留给滚动条的 24px 留白一起圈进了框里 ——
  用户看到的「右闭合」在窗口边，而不是列尾；
- 底边被外框强行闭合。

qfw 的 QSS 里没有任何「只画右边、且画在列尾」的开关：`setBorderVisible` 是全有或全无。
想「底边没有、右边在列尾」，只能**关掉外框、右边线自己画**。

## 结论

1. **关掉外框**：`self.format_table.setBorderVisible(False)`，同时删掉 `setBorderRadius(8)`
   （没有外框，圆角无从体现，四角即直角）。

   关掉之后不用补别的：上边仍由表头各格的 `top border` 横向连成（命中
   `QTableView[isBorderVisible=true]` 时才有那条 `border-top: none`，属性关掉后不再生效）、
   左边仍由行号列（纵向表头）各格的 `left border` 纵向连成；**右边和下边本来就没有任何来源**
   → 有数据时下边天然消失（空表时由自绘补，见「补记 3」），右边交给自绘。

2. **右竖线自绘**：新增 `_TableEdgeRule(QWidget)` —— 1px 宽、
   `WA_TransparentForMouseEvents`（压在表头/数据行上，不许挡点击）、颜色与表头格线同口径
   （亮 `rgba(0,0,0,15)` / 暗 `rgba(255,255,255,21)`），订阅 `qfw.qconfig.themeChangedFinished` 重绘。
   作为表格的子控件放在 `x = 列尾`、`y = 0`、`height = 表格高`，`raise_()` 压在表头之上。

   同一个类也用来补**空表专用的左边线和底边线**（见下方「补记 2」「补记 3」）：
   左边线本来由行号列（纵向表头）各格的 `left border` 连成，底边本来就没有任何来源；
   而表格 0 行时纵向表头宽度就是 0 —— 空表原本只剩上边和右边（半框），
   现在是完整的方框；**一有数据就把这两条撤掉、恢复右下开口**。

3. **位置跟随列宽**：`_distribute_columns()` 末尾调 `_sync_edge_rules()`。触发点不止
   `resizeEvent`：行号列宽度、滚动条显隐都会改 viewport 宽度却不发 `resizeEvent`，所以
   还要重写 `_FormatTable.updateGeometries()`（Qt 在表格几何重算后必调的口子）再同步一次，
   否则填完数据后竖线会停在「表格还没填数据」时的位置（见下方「补记 1」）。

```python
# _FormatTable.updateGeometries()
super().updateGeometries()
if not self._geometry_syncing:          # 防 _distribute_columns 里的 setColumnWidth 递归
    self._geometry_syncing = True
    try:
        self._distribute_columns()
    finally:
        self._geometry_syncing = False

# _FormatTable._sync_edge_rules()
content_end = (self.verticalHeader().width()
               + sum(self.columnWidth(i) for i in range(self.columnCount())))
x = min(content_end, max(self.width() - 14, 0))   # 兜底：别压到滚动条（控件右侧 13px）
self._place_edge_rule(self._right_rule, x, 0, 1, self.height())     # 右竖线 → 列尾
if self.verticalHeader().width() > 0:             # 有行号列时左边线由表头格线自己画，
    self._hide_edge_rule('_left_rule')            # 不能再叠一条（15/255 的透明度会加深）
else:
    self._place_edge_rule(self._left_rule, 0, 0, 1, self.height())  # 空表补左边线
if self.rowCount() > 0:                           # 有数据：底边保持开口
    self._hide_edge_rule('_bottom_rule')
else:
    self._place_edge_rule(self._bottom_rule, 0, self.height() - 1, x, 1)  # 空表补底边线
```

**踩到的坑（关键）**：`columnWidth()` 是 **viewport 内坐标**，而竖线是表格的子控件，
坐标系还包含左侧行号列（纵向表头）。第一版直接把 `sum(columnWidth)` 当 x，
实测整条竖线**偏左 46px**（正好等于 `verticalHeader().width()`），落进了「编码」列中间。
必须补上行号列宽度。

## 补记（装上构建实测后补的三处）

第一版只验证了「窗口尺寸变化」这条路径，装上真机后用户反馈：**嗅探成功、表格被填入数据后
线就偏移了**（截图里竖线落在列尾左侧约 33px）。顺着这条线又查出空表少一条左边线、以及
「空表时应该是个完整的框」，一并补上。

### 补记 1：填充数据后竖线偏左（只监听 `resizeEvent` 不够）

实测（离屏、同一窗口 1131×731）各阶段的行号列宽度与列宽总和：

| 阶段 | `verticalHeader().width()` | `viewport` 宽 | 竖线 x | 应在 | 偏差 |
|---|---|---|---|---|---|
| 刚构造（0 行） | 0 | 578 | 553 | 553 | 0 |
| 填 1 行 | 33 | 545 | 519 | 552 | **−33** |
| 填 10 行 | 46 | 532 | 538 | 551 | **−13** |
| 再 `resize` 同一尺寸 | 46 | 532 | 538 | 551 | **−13（不自愈）** |

原因：**表格被填入数据时，Qt 不会发 `resizeEvent`**，但行号列从「0 行 → 有行」会凭空长出
30~46px 宽、滚动条也会显隐，`viewport().width()` 因此变化；而 `_distribute_columns()`
只在 `resizeEvent` 里调用 → 列宽和竖线都停在构造时空表算出的值上。旧版的「五档窗口实测」
恰好都在填完数据后手动调了一次 `_distribute_columns()`，把这个坑盖住了。

修法：重写 `_FormatTable.updateGeometries()` —— `QTableView` 在行高/列宽/表头/滚动条几何
重算后必调它，是「几何变了但没 `resizeEvent`」的正解。加一个 `_geometry_syncing` 标志位防
`_distribute_columns()` 内部 `setColumnWidth()` 递归触发。修后同样四个阶段偏差全为 0。

### 补记 2：空表少一条左边线（半框）

关掉外框后，左边线唯一的来源是行号列各格子的 `left border`；而**表格 0 行时纵向表头宽度
就是 0**（实测确认，不是被隐藏），那条线整段消失 —— 刚进嗅探页 / 清空结果后切到表格视图，
框只剩「上 + 右」两条边，像画了一半。

修法：`_sync_edge_rules()` 里判断 `verticalHeader().width() == 0` 时，用同一个
`_TableEdgeRule` 补一条 `x = 0` 的左边线；一旦有了行号列就 `hide()` 掉它（行号列那条线在
x=0 的同一像素上，叠着画会把 `alpha=15/255` 加深一档）。空表左边线宽度也验证过是 1px。

另一个坑：窗口显示之后**动态 new 的子控件默认是隐藏的**，第一版左边线 `x` 对、`isVisible()`
却是 False —— `_place_edge_rule()` 里补了 `rule.show()`。

### 补记 3：空表补一条底边线（有数据后仍然开口）

用户补充要求：「**仅在**空表的情况下加上下边线」。理由很直接 —— 空表时既没有行号列、
也没有滚动条，整个框如果只在底部开口，看着像没画完；一旦有数据（右下都要避让滚动条、
也要表达「还能往下滚」），才保持开口。

修法：同一个 `_TableEdgeRule` 再加一条 `_bottom_rule`，几何 `(0, height()-1, 列尾 x, 1)`；
`_sync_edge_rules()` 里按 `rowCount() > 0` 决定 `hide()` 还是摆到位。底边线**右端与右竖线
共用同一个 `x`（列尾）**，所以空表是一个四条边都落在列尾上的完整矩形。

坑：`rowCount()` 只在 `setRowCount` / `removeRows` 时变，而表格填充与清空都必然重算几何，
`updateGeometries()` 一定会进来，所以这里同样不需要额外订阅信号。验证覆盖了
「空 → 填 10 行 → 清空」三段，底边线在第二段消失、第三段自动回来。

## 没采用的替代做法

| 做法 | 为什么不用 |
|---|---|
| 保留外框，把 `table_layout` 右距改回 24 | 表格不再铺满，滚动条从距窗右 4px 退回 28px，决策 49/54 的「滚动条与默认视图同位」当场破功；而且底边仍然闭合 |
| 追加 QSS：`QTableView[isBorderVisible=true]{ border:1px solid transparent; border-right:1px solid rgba(0,0,0,15) }` | 外框永远贴控件边，只能落在视口最右（在滚动条留白的内侧），到不了列尾；底边还得再补一条 `border-bottom: none`，颜色也要亮/暗两套硬编码 |
| 最后加一个占满 `RIGHT_RESERVE` 的空列，让外框右边正好落在列尾 | 会多出一个「幽灵列」（表头多一格、参与选中/排序/复选逻辑），且底边仍闭合；外框与列宽互相绑定，窗口缩放取整时会错位 |
| 在 `_FormatTable.paintEvent()` 里画右边线 | 表头是**子控件**，会盖住表格自身的绘制；而且 `paintEvent` 的坐标系不含 viewport 的滚动偏移，位置要自己算，不如独立子控件直观 |
| 空表时给纵向表头设一个最小宽度（强行留出行号列） | 空表会凭空多出一条空白的行号列，列宽和竖线也跟着换位置；行号列宽度本该由行数内容决定，为了一条线去改它属于本末倒置 |
| 有数据时 `setBorderVisible(False)`、空表时再 `setBorderVisible(True)` 让外框回来 | 空表的右框会跳回「控件右缘」（把 24px 滚动条留白也圈进去），与有数据时的「右框在列尾」不是同一条线，切换时会明显跳一下；还得重新处理 55 的圆角问题 |
| 用 QSS `QTableView[isEmpty=true]{ border-bottom: 1px solid ... }` 补底边 | 属性要在填充前后手动 `setProperty` + `updateDynamicStyle`，且 QSS 边框只能画在控件外缘（右端会跑到滚动条留白外侧），与右竖线的列尾口径不齐 |

## 实测效果（离屏 FluentWindow，`QT_QPA_PLATFORM=offscreen`）

离屏平台没有字体目录，第一版验证时表宽是 578、行号列偏宽（与真机不符）。后面把
`C:\Windows\Fonts\msyh.ttc` 用 `QFontDatabase.addApplicationFont()` 挂上去之后，表宽 594、
行号列 38，和真机（决策 55 实测表宽 594、行号列约 36）对上了。下表是挂字体的数字：

| 窗口 | 表格宽 | 空表列尾 x | 填 10 行列尾 x | 距窗右 |
|---|---|---|---|---|
| 966×731 | 466 | 938 | 942 | 24~28 |
| 1131×731 | 594 | 1104 | 1105 | 26~27 |
| 1440×900 | 771 | 1414 | 1413 | 26~27 |

1131 档与用户截图同尺寸：物理 1105×2.25 ≈ 2486，用户红线实测 2477~2484（中心 2481）。

空表 / 填 10 行 / 清空 三段 × 每段 18 条断言（合计 55 条）全过：

- 几何：列宽不溢出 viewport、右竖线几何 = `(列尾, 0, 1, 表高)`、竖线不压滚动条
  （`滚动条 x = 表宽-13` 未变）、`isBorderVisible == False`、表格右缘仍贴窗口右缘、
  下载按钮仍 240 宽、**空表时有左边线 / 有行号列时自绘左边线自动隐藏**、
  **空表时有底边线且几何 = `(0, 表高-1, 列尾, 1)` / 有数据时底边线隐藏**。
- 像素：表头处与数据行处的竖线都在列尾 ±1px、列尾到滚动条之间的留白内没有任何竖线、
  左竖线在（空表也校验）、竖线纵向连续（全高无缺口）、顶边线止步于列尾、
  **空表底边有整条横线且止于列尾 / 有数据时底边无任何横线**。
- 亮色/暗色各跑一遍；`QT_SCALE_FACTOR=2.25` 下重跑同样全过。
- 另一支探针跑「切默认视图 → 隐藏期间拉大窗口 → 切回表格视图 → 填 6 行 → 缩窗口」，
  每一步右竖线几何都等于期望值（说明 `updateGeometries` 覆盖了隐藏/恢复路径）。

## 风险

1. **竖线是全高**（y 从 0 到底部），含最后一行下方的空白区 —— 与用户红线画法一致；
   若以后想让它在「最后一行底」收尾，改 `height` 即可。
2. **距窗右在 24~28 之间浮动**（24 + 5 列比例取整的余数，空表/有行号列还差一档），不是恒定 24；
   想恒定要先按比例取整再补余数，本决策没做（用户没提，视觉上无差别）。
3. **若以后又打开 `setBorderVisible(True)`，右竖线会变双线**（外框 1px + 自绘 1px），
   并且底边重新闭合。改这段前先看本文。
4. **`_right_rule` / `_left_rule` / `_bottom_rule` 都是表格的子控件**：大改表格属性（隐藏/替换）时
   别把它们孤立掉；`raise_()` 保证压在表头之上（底边线在表格最下一行像素、不压内容），
   以后给表格加浮层控件要重新 `raise_()`。
5. **依赖 `verticalHeader().width()`**：既用来补「列尾」的坐标系偏移，也用来判断空表
   （宽度为 0 才补左边线）。若以后隐藏行号列，该宽度变 0：位置自动适配、左边线改由自绘
   补上（正好是想要的效果），但「补行号列宽度」这个口径不能删。
6. **依赖 `updateGeometries()`**：行号列宽度、滚动条显隐这类「不发 `resizeEvent` 的几何变化」
   只能从这里兜。若以后在 `_FormatTable` 里再重写 `updateGeometries()`，必须保留
   `super()` 调用 + 末尾同步，否则竖线会重新变回「填完数据就偏」。
7. 暗色主题的线色为 `rgba(255,255,255,21)`（与 qfw 表头格线一致），深色背景下很淡 ——
   与决策 55 时期观感一致，未另调。
8. **窗口窄到列宽总和超出控件宽度时**（`COL_MIN = 50` 兜底，约需窗口 < 780），「列尾」在控件外，
   竖线被钳在「距控件右缘 14px」（避开滚动条）—— 本程序窗口最小宽 917，实际不可达，
   兜底只为不崩、不压滚动条。极小窗（400×400）实测竖线落在 x=250、无异常。
9. **底边线只看 `rowCount()`**：只要有一行就撤掉（哪怕行被 `hideRow` 隐藏），口径是
   「空表才框起来」；若以后要按可见行判断，把 `rowCount()` 换成可见行统计即可。
   底边线的右端与右竖线共用同一个 `x`，两者不会出现「差一像素」的错位。
