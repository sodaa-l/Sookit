# 决策 35. 嗅探页「下载封面」的文件名归属（2026-10-13）

> 决策索引：[DEVELOPMENT.md](../DEVELOPMENT.md#决策索引)（编号与代码注释里的「决策 35」一一对应）

**症状**：嗅探视频1 完成后，输入视频2 的地址并点「嗅探」，在视频2 嗅探完成前点「下载封面」——
下载到的**封面内容是视频2 的（对的），文件名却是视频1 的标题**。

**根因**：封面面板的两半状态更新时机不同，而命名只取了其中滞后的那一半——

- `do_sniff` 里**同步**做的：`_sniff_video_id = extract_youtube_id(url)`（新链接）、
  `build_thumbnails()` 重填 `cover_combo`、异步预载预览（决策 17「立即从 URL 取 ID」的设计）→
  「封面内容/下载 URL」当场就属于新视频；
- `_sniff_title` 只在 `_on_sniff_done`（嗅探**完成**）里赋值 → 这中间的文件名仍按上一部视频的标题拼；
  `_download_cover` 的 `if self._sniff_title:` 分支正好取了这个尚未更新的字段。

失败路径 `_on_sniff_error` 本来就清空 `_sniff_title`，说明「嗅探没成功就没有可信标题」是既有口径，
只是 `do_sniff` 漏了这一步。

**口径（本次确定）**：封面文件名只能来自「当前封面面板所属的那部视频」。

- 嗅探**进行中**下载 → 用当前链接解析出的 **ID**（标题此时尚不可知，不做猜测）；
- 嗅探**完成后**下载 → 仍用**标题**（原行为，可读性更好）；
- 嗅探**失败 / 超时 / 停止**后下载 → 用 ID（与失败路径既有清空口径一致）。

**实现**：`pages/youtube_page.py` 的 `do_sniff` 在「清空封面」处补三行，开始新嗅探即一并作废
`_sniff_title` / `_sniff_channel` / `_sniff_duration`（+7 行含注释）。清 channel/duration 是顺手的一致性：
它们同样只在嗅探成功后才可信，且只被入队消费（入队按钮在嗅探失败时本就禁用）。

**刻意不做**：不在嗅探中禁用「下载封面」——封面列表与预览本来就是同步可用的，禁用反而降低可用性；
标题未知时回退 ID 是诚实且可预期的命名。

**验证（2026-10-13 离线冒烟，`QT_QPA_PLATFORM=offscreen`，全程打桩不触网，14 项断言全过）**：

- 视频1 完整嗅探 → 按标题命名 `视频一标题_cover.jpg`；
- 视频2 点嗅探后（未处理完成信号）：`_sniff_title` 已清空、`_sniff_video_id` 已是视频2、下拉框已换成
  视频2 的封面 → 下载得到 `bbbbbbbbbbb_cover.jpg`（**不含视频1 标题**），且下载 URL 属于视频2；
- **反证**：手动把 `_sniff_title` 塞回视频1 的标题 → 文件名立刻变回 `视频一标题_cover.jpg`（原错配复现）；
- 视频2 嗅探完成后 → `视频二标题_cover.jpg`；嗅探失败后 → 回退 ID 命名。
