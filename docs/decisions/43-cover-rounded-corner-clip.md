# 决策 43. 封面圆角裁剪必须按控件 rect + 开抗锯齿（2026-10-18）

> 决策索引：[DEVELOPMENT.md](../DEVELOPMENT.md#决策索引)（编号与代码注释里的「决策 43」一一对应）

## 背景

用户提出「动图下载功能中，能否给动图封面也加上圆角」。按文档口径，动图卡封面既有圆角配置
（`_GifCover.RADIUS = 8`，决策 37），代码也确实调了 `addRoundedRect`，但**真机上四角是方的**——
配置在、渲染却没生效。

离屏复现（`QT_QPA_PLATFORM=offscreen`，封面整块填 `#1e785a`，读四角像素）暴露两个**叠加**的成因：

| 源图 | 控件 | 修复前四角 | 修复后 |
|---|---|---|---|
| 1200x675（16:9） | 228x135（动图卡） | `1e785a` = 封面本色，**直角** | `efefef` = 底色，圆角 |
| 600x600（1:1） | 228x135 | `1e785a`，**直角** | `efefef`，圆角 |
| 600x600（1:1） | 270x152（队列页卡） | `1e785a`，**直角** | `efefef`，圆角 |
| 228x135（与控件同尺寸） | 228x135 | `efefef`，圆角 | 不变 |

**成因一（决定性）：圆角裁剪路径建错了坐标系。** `RoundedCoverWidget.paintEvent` 用
`KeepAspectRatioByExpanding` 缩放，得到比控件**更大**的 `scaled`（1200x675 → 240x135），再按
`x=(228-240)//2=-6, y=0` 居中。旧代码把裁剪路径建在**这张图**上：

```python
clip.addRoundedRect(QRectF(x, y, scaled.width(), scaled.height()), radius, radius)
```

四个圆角因此落在 `x<0` / `x+240>228` 的控件外，被控件边界（`QWidget` 的绘制范围）整块切掉，
剩下可见部分全是直边——**圆角配置写对了，但圆角根本没落在控件里**。只有源图比例恰好等于控件
比例（`scaled == rect.size()`，`x=y=0`）时两者重合，圆角才碰巧成立；这也解释了为什么这个 bug
在开发期不容易被发现（16:9 素材配 16:9 控件）。

**成因二（次要但真实）：`paintEvent` 没开 `Antialiasing`。** 该函数只设了
`SmoothPixmapTransform`，圆角边缘无抗锯齿。8px 圆角在无 AA 下退化成约 2px 的硬台阶
（对角采样 `efefef → 1e785a` 一步跳变），即使坐标修对了，肉眼仍接近方角。A/B 实测四种组合
（裁剪路径 × AA，10x10 角部背景像素数）：旧路径 0/0、新路径无 AA 12、新路径有 AA 10——
但像素计数受分类阈值影响有限，真正区分度在视觉：开 AA 后对角出现中间过渡色
`efefef → 508a7d → 1e785a`，肉眼是平滑弧线。

## 结论

- **封面圆角裁剪路径一律按控件 `rect` 建**（`QRectF(rect)`），不要按缩放后的 pixmap 建。
  居中偏移 `x/y` 只用于 `drawPixmap(x, y, scaled)`，不参与裁剪路径——溢出的部分本来就该被控件
  边界裁掉，圆角要在**控件**的四角上。
- **`RoundedCoverWidget.paintEvent` 必须开 `QPainter.RenderHint.Antialiasing`**：圆角、图标、
  占位文字都靠它平滑。
- 该控件被动图页（`_GifCover` 子类）与队列页任务卡（`YtDlpTaskCard` / `FfmpegTaskCard`，均为
  270x152）共用，故**一处修复同时生效于两页**；队列页此前只在源图非 16:9 时才暴露，
  属于潜伏同类问题，本次一并修好。
- `CoverAreaWidget`（已完成页，`paintEvent` 用的就是 `QRectF(rect)`）与 `CoverImageWidget`
  （嗅探页，radius 16）不走这条路径；前者本就正确，后者实测四角正常，本次**未改动**。

## 验证

离屏（`QT_QPA_PLATFORM=offscreen`，不触网）26 项断言全通过：

- **比例矩阵**：16:9 / 4:3 / 1:1 / 9:16 竖图 / 与控件同尺寸 / 超宽 2560x400，六种源图在 228x135
  动图卡上四角均被切圆、内部仍是封面本色。
- **弧线质量**：对角线上出现中间过渡色（抗锯齿成立），非单步硬跳。
- **交互不回归**：选中徽标仍画在右上角（`255,255,255` 白勾）、悬停压暗仍生效
  （`30,120,90 → 25,101,76`）且压暗同样被圆角裁住、不漏到角外。
- **占位分支**：`setText()` 占位下四角仍是圆角、文字仍绘制。
- **队列页**：1:1 源图在 270x152 卡片上四角圆角（修复前为直角）。
- **整页冒烟**：解析出 3 张卡片、默认全选、**解析前后版式零位移**（决策 37 的硬约束，
  `(99,240) → (99,240)`）、卡片封面仍 228x135。
- 另在未设 `PYTHONUTF8` 的环境下跑了 import 与 `compileall`，无编码问题。

**取色说明**：离屏渲染下光标默认停在 (10,10)，窗口一 `show()` 就命中悬停态把封面压暗，
采样会拿到 `25,101,76` 而不是本色 `30,120,90`。测试里需把窗口 `move(1000,1000)` 挪开再采样。
