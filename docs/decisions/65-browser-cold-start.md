# 决策 65. 浏览器静默冷启动的日志、首次窗口尺寸与提示定位

## 问题与原因

扩展首次调用会通过 Native Host 启动 `Sookit --silent`，GUI 标准流连接 `DEVNULL`。Windows 中文环境下，Python 的文本 stdout 仍可能采用 GBK。`PageBase.log()` 原来先 `print(msg)` 再写日志；嗅探启动 worker 后输出 `▶ 正在嗅探视频信息...` 时，`▶` 无法用 GBK 编码，异常经本机通道变成失败回执。因此会出现网页报错，但 worker 已开始并最终嗅探成功，同时日志异常还会跳过 60 秒超时计时器的创建。

窗口缩小是另一个独立问题。Windows 无边框组件构造期间创建原生窗口并使用初始 500×500；Sookit 随后在隐藏状态设置 1131×731。静默启动先运行事件循环，旧的原生尺寸消息把隐藏窗口重新改为 500×500，甚至小于声明的 966×644 下限；之后托盘或通知调用 `show()` 不会恢复期望尺寸。普通启动立即显示，未出现这次回退。原生 Windows、300% 缩放下已以控件尺寸数据复现，无需截图。

## 实现

- `PageBase.log()` 只调用现有 `Sookit` logger。入口已经配置控制台 handler 和 UTF-8 文件 handler，保留完整 Unicode 日志并消除重复输出；日志不会再通过裸 `print()` 抛异常打断已启动的操作。
- `MainWindow.INITIAL_SIZE` 统一为 `(1131, 731)`。首次 `showEvent()` 恢复该尺寸并居中，再执行父类显示处理；之后隐藏、显示不再重置尺寸或位置，用户手动调整仍然有效。
- 浏览器请求继续只在后台受理，尺寸恢复发生在用户首次显示主窗口时，不通过预先显示窗口解决问题。

## InfoBar 首次显示定位补充

隐藏期间创建的 InfoBar 会在父窗口正式显示时启动滑入动画。子控件的显示处理可能先于 `MainWindow.showEvent()` 的尺寸恢复，动画终点因此按旧的 500px 窗口宽度计算；父窗口随后虽然恢复为 1131px，动画仍会把提示条拉回旧坐标。原生测量中，短提示 x 为 -30、正确值为 601，长提示 x 为 -159、正确值为 472，页面内提示也同样偏移 631px。旧封装只为长文案安排创建后 0/100ms 校正，这些回调可能在隐藏期间就执行完；短提示更没有对应校正。

`show_infobar()` 现在为所有提示条安装随条销毁的事件过滤器，监听提示条及其父控件的显示、尺寸、布局和窗口状态变化，用单次 0ms 定时器合并事件，待布局完成后执行 `_settle()`。校正会重排同一父控件下的整组提示；滑入或收拢动画尚在运行时更新其终点，避免逐帧覆盖正确位置。保持现有换行方式、右上角边距及动画，已销毁控件的守卫沿用决策 32。

## 验证

```bash
uv run --no-sync python -X utf8 -m unittest discover -s tests -p test_browser_startup.py -v
```

两项回归覆盖：

1. 使用真实 `sniff_from_browser()` → `do_sniff()` → `PageBase.log()` 调用链，在 GBK 严格 stdout 和 stdout 为 `None` 时均返回成功、启动 worker、创建 60000ms 计时器，完整 `▶` 日志进入 logger。耗时 worker 与封面请求使用替身，不访问视频平台。
2. 独立 Windows 原生 Qt 进程比较普通启动与静默启动先处理事件、后显示窗口两条路径；首次显示均为 1131×731 且居中，隐藏前不显示窗口，手动改为 1240×800 后再次打开保持该尺寸。两条路径各校验 7 个提示场景：隐藏期间创建的长短提示及自定义按钮、页面内提示；滑入动画期间缩放；关闭上方提示时缩放；后台页面首次显示；切回页面；隐藏后再次显示；定时回调执行前关闭并销毁提示。独立断言右边距为 24px、条间距为 16px。测试隔离配置、任务历史、workspace 清理和设置页版本检查，不触碰用户记录、不联网、不截图。非 Windows 环境跳过原生尺寸与定位测试。

真实 Chrome 端到端启动和系统通知的人工验收边界沿用决策 62。
