# 决策 49. 嗅探页默认视图滚动条贴窗口右缘（2026-10-21）

> 决策索引：[DEVELOPMENT.md](../DEVELOPMENT.md#决策索引)（编号与代码注释里的「决策 49」一一对应）

## 背景

决策 47 把嗅探页默认视图改成两列卡片后，卡片区右侧常出现一条竖向滚动条
（内容略高于视口时）。它贴着**卡片区**右缘，距窗口右缘 28px，中间隔着一整条
页面留白，看上去像是浮在界面中间、而不是窗口自带的滚动条。

用户要求：**滚动条贴窗口最右端，而不是贴在卡片区最右端。**

## 根因

页面右侧一共有 4 层缩进叠加，滚动条只能落在最内层容器的右缘：

| 层 | 右缩进 | 位置 |
|---|---|---|
| `page.layout()` 主布局 | 20 | `youtube_page.py` `setContentsMargins(20, 20, 20, 20)` |
| 右面板 `right_layout` | 4 | `setContentsMargins(8, 4, 4, 4)` |
| `default_layout` | 0 | — |
| `option_layout`（卡片列表） | 6 | `setContentsMargins(0, 0, 6, 0)` |
| qfw 滚动条自身 | 4 | `ScrollBar._adjustPos` 右缩 1 + `_adjustHandlePos` 手柄再缩 3 |

合计 20 + 4 + 0 + 6 + 4 = **34px** 中的 28px 是布局造成的（另 6px 在滚动条内部）。
`qfw.ScrollBar` 是滚动区的子控件，位置由 `_adjustPos` 按滚动区宽度算，**没有
「贴到父窗口右缘」这个选项**——它必然贴着自己的滚动区。所以只能反过来把滚动区
本身的右缘推到窗口右缘。

## 备选方案与取舍

| 方案 | 做法 | 结论 |
|---|---|---|
| A 负右边距 | `default_view.layout().setContentsMargins(0,0,-24,0)`，让滚动区向右溢出 | **否决**。Qt 的 `QLayout` 不支持负边距，实测滚动区反而收缩到距右 33px、卡片缩到 199px |
| B 只给滚动区单独外扩 | 用 `move()` / 绝对定位把 `option_scroll` 拉到窗口右缘 | **否决**。脱离布局管理后，窗口缩放、视图切换、splitter 拖动都要手动重算，且滚动区会压到 `SegmentedWidget` 和下载按钮的右侧空白，与它们不对齐 |
| C 只清主布局右距 | `page.layout()` 右外距 20→0 | **否决**。20px 被 URL 行、标题、表格、`SegmentedWidget`、下载按钮**全部共用**，清了以后 URL 行右距 286→266、表格视图右距 24→0、卡片宽 216→228，所有这些都跟着右移，属于把问题从一个地方转移到另一个地方 |
| **D 清右距 + 逐行补回（采用）** | 主布局右距 20→0、右面板 4→0，然后**每一行各自补回**原来的右边距 | 滚动条贴边，同时其余控件的位置和宽度**与改动前逐像素一致** |

## 结论

采用方案 D，改动 5 处边距（`src/sookit/pages/youtube_page.py`）：

| 位置 | 改动 | 目的 |
|---|---|---|
| `page.layout()` | `(20, 20, 20, 20)` → `(20, 20, 0, 20)` | 让出 20px，右面板得以贴到窗口右缘 |
| `url_row` | 新增 `setContentsMargins(0, 0, 20, 0)` | 补回 URL 行右距，输入框宽度不变 |
| `right_layout` | `(8, 4, 4, 4)` → `(8, 4, 0, 4)` | 让出 4px |
| `option_layout` | `(0, 0, 6, 0)` → `(0, 0, 30, 0)` | 6 + 20 + 4 = 30，卡片右缘原位，滚动区贴边 |
| `table_layout` | `(0, 0, 0, 0)` → `(0, 0, 24, 0)` | 20 + 4 = 24，表格与表格视图按钮右缘原位 |
| `default_btn_row` | 新增 `(0, 0, 24, 0)` | 同上，默认视图下载按钮不右移 |

**关键点：`option_layout` 的右内距是 30 而不是 6**。滚动区已经贴到窗口右缘，
但卡片列表若仍只留 6px，卡片就会一路顶到滚动条上。补回 20+4 = 24px 后，
卡片的右边缘与改动前完全重合，多出来的位置正好被滚动条占用——视觉上滚动条
落在「本该空着的页面留白」里，卡片布局一点没动。

## 效果（966×644 实测，7 档两列）

| 项 | 改动前 | 改动后 |
|---|---|---|
| `right_panel` 右距 | 20 | **0** |
| `option_scroll` 右距 | 24 | **0** |
| 滚动条轨道右距 | 25 | **1** |
| **滚动条手柄右距** | **28** | **4** |
| `url_input` | x=69 w=611 右距 286 | 完全一致 |
| 卡片宽 / holder 宽 | 216 / 442 | 完全一致 |
| 表格视图 `format_table` 右距 | 24 | 完全一致 |
| 下载按钮（两视图） | 240×32 | 完全一致 |
| `page.minimumSizeHint().width()` | 709 | 709（未上升，左栏不会被挤压） |

窗口 966 / 1005 / 1131 / 1400 四档下，手柄距窗口右缘**恒为 4px**；左栏宽度
412 / 412 / 456 / 571 与改动前一致。

## 风险

1. **每一行都要记得补回右距**。以后往页面里加新的右对齐控件（比如再添一行
   按钮或输入框），如果直接 `layout.addWidget(...)` 而不单独设右内距，它会
   比老控件多右移 20px。这是方案 D 的固有代价——把「统一缩进」换成了「逐行
   缩进」。已在 `DEVELOPMENT.md` 的决策索引里写明。
2. **`right_layout` 是 `__init__` 里的局部变量**（`right_panel` 同理），没有
   存成 `self` 属性。测试或后续改动要取它只能用
   `page.findChild(QSplitter).widget(1).layout()`。
3. 改动只影响 sniff 页，不影响其他页面；`qfw.ScrollBar` 自身的 4px 内缩是
   库内固定值，改它需要 monkeypatch（决策 48 已铺了同样的路，但此处不值得
   为 4px 再打一个补丁）。

## 验证

1. `uv run python -m compileall -q src/sookit/pages/youtube_page.py` 通过。
2. 真实 `FluentWindow` + 7 条伪造格式，966×644 下逐项断言：滚动区右缘 ==
   窗口右缘、手柄距右 4px、URL 行右距 286、卡片宽 216、左栏 412、
   `minimumSizeHint().width() == 709` —— 29 项全绿。
3. 窗口 966 / 1005 / 1131 / 1400 四档，手柄距右恒 4px，左栏不被压。
4. 表格视图无回归：表格右距 24、按钮 240×32 与改动前一致。
5. 功能回归：档位生成 7 行、无「最佳」文案、预选最高档、两列、
   滚动区透明、单选互斥、`do_download_default` 传入的 spec 正确、
   清空后空态回来。
6. 渲染 966×644 整数窗口截图，肉眼确认滚动条贴到窗口右缘，卡片与按钮
   位置未变。
