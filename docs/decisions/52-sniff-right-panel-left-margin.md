# 决策 52. 嗅探页右面板统一左留白：视图切换、档位卡片、格式表格左边缘对齐（2026-10-20）

## 背景

决策 50 给档位卡片做了左右对称留白（左 15 / 右 15 + 滚动条让位），
决策 51 又去掉了卡片 400px 的宽度上限。此时右面板内三块内容的左边缘并不在一条线上：

| 元素 | 改前 x（1131×731 实测） | 原因 |
|---|---|---|
| 视图切换 `SegmentedWidget` | 538 | 右面板 `right_layout` 左内距 8 |
| 档位卡片（默认视图） | 553 | 538 + `option_layout` 左内距 15 |
| 格式表格（表格视图） | 538 | 右面板左内距 8 + `table_layout` 左内距 0 |

即卡片比按钮和表格右缩了 15px。用户实测后提出：表格视图也要一样的左留白，
并且视图切换按钮要对齐默认视图卡片的最左端。

## 结论

把「左留白」的归属上提到右面板这一层，三块内容共用同一个内距，各自左内距归 0：

```python
class YouTubePage(PageBase):
    OPTION_MARGIN_X = 15   # 右面板统一左留白
    SCROLLBAR_RESERVE = 13 # 滚动条浮在视口右缘占的宽度
```

| 位置 | 改前 | 改后 | 说明 |
|---|---|---|---|
| `right_layout`（右面板） | `(8, 4, 0, 4)` | `(15, 4, 0, 4)` | **唯一的左留白来源** |
| `option_layout`（卡片列表） | `(15, 0, 15, 0)` | `(0, 0, 15, 0)` | 左内距归 0；右侧仍是 15 + 滚动条让位 |
| `table_layout`（表格视图） | `(0, 0, 24, 0)` | 不变 | 左内距本来就是 0，右 24 是决策 49 的补偿 |
| `default_btn_row` | `(0, 0, 24, 0)` | 不变 | 同上 |

于是三者左边缘都等于「右面板左缘 + 15」，而右面板左缘 = 主布局左 20 + splitter 位置。

### 为什么左留白放在右面板而不是各子块

放在子块上时，「对齐」靠三个数字（8 + 15 = 8 + 0）凑巧相等来维持，
以后任何一个子块调边距都会重新错位。放到右面板上后，对齐是**结构保证**：
子块左内距一律 0，只有一处数字决定左边缘。

### 为什么右边距不动

右面板右内距仍是 0，`option_layout` 右侧仍是 `15 + 13 = 28`（决策 53 后已固定）。
决策 49 建立的前提是「滚动区贴到窗口右缘」，决策 50/53 建立的前提是
「卡片右缘到滚动条左缘 = 15」。这两条都不涉及左边缘，所以左留白上提不影响它们。

## 风险

1. **右面板左内距变成 15 后，任何新加进右面板的控件默认也带 15 左留白。**
   这正是想要的效果，但如果以后要加一个需要贴左缘的控件，必须自己把内距设回 0。
2. **`option_layout` 左内距变成 0 后，「左留白」不再由卡片列表自己控制。**
   以后想把卡片区整体左移/右移，要改 `OPTION_MARGIN_X`，不要改 `option_layout` 的左内距。
3. **最小宽度从 709 涨到 716。** 不影响布局（窗口最小 966），但若以后右面板再加内容，
   这个数字会继续涨，需要留意不要超过 splitter 的左栏需求。

## 验证

1. 966/1005/1131/1300/1400/1600/1920 七档窗口，`segment.x == card0.x` 全部成立。
2. 切到表格视图后 `segment.x == format_table.x` 成立，切回默认视图仍成立。
3. 卡片左缘 == `option_scroll` 左缘（左内距 0 生效）。
4. 卡片右缘到「滚动条左缘（可见）/ viewport 右缘（不可见）」恒为 15（±1 取整）。
5. 表格右距窗口 24、两个下载按钮 240×32，与决策 49 的结论一致（无回归）。
6. 清空档位后右边距复位 15、左内距仍 0；空态提示回来。
7. 左栏在 966/900/820 下恒为 412（不受右面板左内距变化影响）。
8. `page.minimumSizeHint().width() == 716 < 917`，窗口最小宽度下不会挤左栏。
9. 冒烟 48 项全绿。
