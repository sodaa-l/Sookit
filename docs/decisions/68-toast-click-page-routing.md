# 决策 68. 系统通知正文点击路由到来源页面（2026-11-02）

> 决策索引：[DEVELOPMENT.md](../DEVELOPMENT.md#决策索引)

## 背景

系统通知原先只负责显示并激活主窗口，点击正文后仍停留在此前页面。用户选择让通知正文打开对应顶层页面；任务队列通知还要显示与任务状态相符的分段，不要求定位具体任务卡片。

## 决策

- Toast 正文点击携带目标页键，经 `notifier._ToastSignalBridge.activate_requested` Qt 信号转回主线程；主窗口恢复并置前后调用 `switchTo()` 导航。
- 页面通知映射：视频嗅探及封面下载结果 → 视频嗅探页；GIF 解析结果 → 动图下载页；频道嗅探结果 → 直播监控页。
- 任务通知映射：浏览器最佳画质下载开始及失败 → 任务队列「进行中」；任务完成 → 任务队列「已完成」。任务通知均进入对应分段，不额外定位任务卡片。切页后显式设置分段，避免队列页既有的自动默认规则覆盖通知目标。
- 更新、yt-dlp 状态和安装包就绪通知 → 设置页。
- `Toast.on_activated` 仍先检查 `args.arguments == open_folder`；成功任务的「打开文件夹」按钮继续独立发出 `open_path_requested` 并打开目录，不触发页面路由。其他点击走目标页键。WinRT 回调只通过 Qt bridge 发信号，不直接操作界面控件。
- 路由仅对仍在运行的 Sookit 进程生效；不增加冷启动行为。未知目标只恢复并显示主窗口。

## 结果

通知点击会把用户带到通知来源对应的顶层页面。既有通知开关、焦点判断、通知内容以及成功任务的打开目录动作保持原流程。
